# Design

## Artifact store

MinIO is the default S3-compatible backend (ADR-047), hidden behind an `ArtifactStore`
interface so S3/R2 can be selected by configuration.

```
agent                         API/worker                     MinIO
  | artifacts command             |                            |
  |-----------------------------> |                            |
  | collect files + metadata      |                            |
  | POST /runner-agent/artifacts/presign                          |
  |------------------------------>| verify host + lease          |
  |<------------------------------| presigned PUT URLs           |
  | PUT blob ---------------------------------------------------->|
  | return artifact keys/hashes   |                            |
  |-----------------------------> | record run artifacts        |
```

- The control plane owns bucket/credentials. Agents never receive long-lived S3 credentials.
- Presigned PUT grants are run-scoped, short-lived and content-length bounded.
- The agent uploads directly; blobs never traverse Temporal or the agent command channel.
- The worker records `storageKey`, `bucket`, `sha256`, `bytes` and `contentType` in the run's
  artifact metadata. A HEAD/checksum verification is best effort; a mismatch is recorded as an
  upload error and does not silently mark the artifact available.
- `patch.diff` is still returned inline for downstream stages. It is also uploaded so the
  console can download it from object storage.
- Downloads use a presigned GET generated by the API after the normal run-access check. Local
  artifacts fall back to the existing run-directory file.

## Presigning

Use AWS Signature V4 query-string presigning without an SDK dependency. The signer takes
method, endpoint, bucket, key, expiry and optional content type/length, and returns a URL.
The endpoint used for signing is the public endpoint agents can reach; a separate internal
endpoint is used for optional HEAD verification. This keeps the agent and API free of an AWS
SDK and works with MinIO path-style addressing.

## Windows agent

- `RUNNER_PLATFORM=windows` selects the native process backend by default.
- The local backend uses PowerShell (`powershell.exe -NoProfile -Command`) instead of
  `/bin/sh`, with Windows-safe quoting and process-tree termination.
- Preflight is a PowerShell script that checks git, PowerShell, Bun, free disk and optional
  MSBuild/dotnet.
- Install is a PowerShell script run from a repository checkout: install Bun if missing, set
  the enrollment env, and start the agent. A production Windows service wrapper is documented
  as a follow-up.
- Metrics use PowerShell/CIM: CPU load, memory, logical disks, uptime and process count.

## macOS agent

- `RUNNER_PLATFORM=macos` selects the native process backend by default.
- The existing `LocalRunnerBackend` uses `sandbox-exec` when `RUNNER_SANDBOX=exec`; otherwise it
  records an explicit unavailable sandbox.
- Preflight is a bash script that checks git, curl, Bun, Xcode command-line tools, disk and
  `sandbox-exec`.
- Install is a bash script run from a repository checkout: install Bun if missing, set the
  enrollment env, and start the agent under `nohup` (launchd service wrapper documented as a
  follow-up).
- Metrics extend the existing `df` path with `sysctl vm.swapusage` and `ps` process count.

## Platform defaults

`RUNNER_BACKEND` defaults to `docker` on Linux and `local` on Windows/macOS. The generated
install command always sets the backend explicitly. The agent passes its platform to the
runtime so metrics, shell selection and sandbox behavior agree with enrollment.

## Playwright E2E

`apps/web/e2e/runners.spec.ts` uses the existing admin storage state:

1. Open `/runners`, assert the empty/healthy state.
2. Create a Windows enrollment through the wizard; assert the PowerShell preflight/install
   commands and the one-time token.
3. Exchange the enrollment token through the agent API, post a heartbeat with CPU/RAM/disk
   metrics, then assert the host appears in the list and detail page.
4. Post a high-CPU heartbeat, assert a firing alert appears, acknowledge it, and delete the
   host.
5. Clean up any created host in `afterEach`.

The test uses the API directly for the agent-side calls because a real Windows host is not
available in CI; the browser flow covers the console surfaces.

## Risks

- MinIO is AGPLv3; self-hosted internal use is acceptable, redistribution needs review.
- Windows/macOS native runners are weaker isolation than Linux containers.
- Presigned URLs require the object store to be reachable from runner hosts; deployments must
  set `S3_PUBLIC_ENDPOINT` to a TLS endpoint.
- No real Windows host in CI; PowerShell generation and metric parsing are unit-tested, but
  live Windows execution remains an operator verification step.
